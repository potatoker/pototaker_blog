再不总结，一些使用经验就要过期发烂了，，在Sora诞生之前，视频生成领域已经是整个AI投资领域追捧已久的一个概念，本文仅从工程使用的角度出发看看前Sora时代利用开源资源大致能将生成式视频做到什么程度。然后就会更加领悟 Sora 的断层式强大。。。

视频生视频

生成式视频领域最简单的一个侧面应该就是视频生成视频，或者叫视频风格化，这个概念其实起源更早，以前 GAN 时代就已经有不少视频风格化的样例，在AnimateDiff 这个工具出现之后，整个StableDiffusion社区已经活跃着很多视频风格化的尝试，B站上也早有很多整活视频，目前业界比较好的效果有如[原视频待补：ssstwitter.com_1708301314479.mp4]如:

这是2.19日domoAI在他的官方twitter 上发布的其最新的视频生视频效果展示，这是目前业界已经拉到不错融资的主打视频生视频的创业公司之一。

video2video 简单理解的话，其实就是把视频拆解为视频帧，简化为image2image 然后增加controlnet 部分保证画面主体与原视频一致，这样生成出来的新风格视频也能与原视频一致，自然也就是连贯的。目前在开源社区内能直接搜索找到不少已经有不错效果的video2video 的workflow.

workflow与概括流程

在看完整的workflow之前可以看下这些视频生视频大概的结构:
[原图待补：原图片尚未取回]

这些 workflow 大致长这个样子，其中最关键的部分是controlnet,

  1. tile： 给画面增加细节的controlNet 模型，细节增加之后可以帮助画面提升稳定性，因为细节越多，画面重绘的限制越多
  2. openPose：这个很熟悉了，提取人物动作和表情，保证人物动作和表情的一致性
  3. depth：画面景深信息，重绘过程中保证画面景深一致性。
  4. hed: 其实线条类的controlNet 模型都可以，除了Hed 还有lineart，softEdge 等其实都可以进行尝试。

controlNet是保证稳定性最关键的Node 之一，基本上这些controlNet 应用的越多，强度越高画面就越稳定，反之画面越不稳定，但风格化越重。

除了controlNet，还有faceResotre 和upscale 放大对画面效果是两个运用了之后就立竿见影的Node，

  • faceResotre: 在很多全身视频作为输入时，脸部修复尤为重要，这个之前使用过人像text2Image应该会很熟悉，不过这里脸部修复的一个缺点是，有相当的概率会丢失一定的脸部表情，比如眨眼，微小等，因为这里的脸部修复本质上重绘了面部，如果需要重新还原这些表情，需要给脸部修复增加额外的表情 prompt。
    [原图待补：原图片尚未取回]

  • upscale: 放大也是一个提升效果非常明显的操作，不过这就取决于当前使用的机器的显存大小了，放大意味着细节的全面提升，和 前面 tile 一样细节提升，画面信息量变大，更精致的同时，重绘也会更稳定。

faceResotre 和upscale 是最常见的两个提升视频效果的节点，其实还有很多其他节点对不同的输入都会有不同程度的效果提升。

  1. LCM Lora: Latent Consistency Model , 这是一个比较常用的用来提升画面生成速度的模型，在video2video 的流程中，其实 LCM 也可以认为提升了稳定性，因为相同的步数下，LCM 收敛之后的效果更好，感觉和前面描述的细节越多时画面越稳定一个原理。总之是一个非常值得嵌入workflow 的 Node，

  2. IP Adapter: Image Prompt Adapter也是最近很火的一个组件，仅通过引用一张图片就可以指导模型最终生成的风格效果，或者应用目标人脸，或者指导生成图片的配色，用处非常广，以前需要使用 Lora 才能实现的很多功能，都可以使用 IP Adapter 轻量级实现。比如使用一张图片作为风格化参考:

最后总结一下就是，如果你本来就是一个text2img玩家，那么只需要注意controlnet的组合运用与强度，以及 LCM 对稳定性以及生成速度的提升，其他就是运用一切图片生成的可用办法提高视频帧质量即可。

抽奖

图生视频

视频生视频实际上仍然可以看作扔停留在图片维度上，它仍然把视频看作连续的图片。但是图生视频才真正上升了一个维度，难度也更大，在前Sora时代，这样生成的视频想要保持稳定，同一幕大概只能保持 5s 左右，而且动作幅度小，动作方式固定，尽管如此，Runway，Pika 等仍然成为了此领域的明星公司。在 B 站上也能看到一批利用这些工具和 MideJourney 产生的“AI”大片：AI悬疑电影预告， 或者是做广告。其实看多了就会发现，前 Sora 时代的图生视频或者文字生视频擅长的是非实体动画（火焰，流水，烟雾）以及简单的镜头推镜，以及人物非常简单以及短暂的动作表情，所以很多人说前 Sora 时代的视频生成是动图生成，其实挺形象的。

在开源领域，能够使用的视频生成模型主要是AnimateDiff 和SVD(Stable Video Diffusion)，整体使用下来图生图方式下，Animatediff 限制更多，效果大多数情况下不如SVD, 不过像Animatediff git 主页展示的例子所示，其对动漫风格的动画效果有时会有一些惊喜。
[原视频待补：animate_diff_00004_ (1).mp4]
但整体泛化性上来说，SVD 的视频效果仍然比 Animatediff 要更稳定，视频本身图像质量也更好。不过 Animatediff 生态中还有如motionLora 这种额外的组件支持，SVD 的可控参数则基本上是在抽奖。
SVD 的主要可控参数就是bucket_id，一般认为bucket_id 越大，动作幅度越大，需要进行多次抽奖找到合适的bucket_id，此外还有Augmentation level 参数，在这篇帖子 的总结中，Augmentation level 大部分情况下作用并不明显，在bucket_id 较大时，会一定程度影响动画。此外，增大sampler 的步数也可以增加最终视频的稳定性，不过这两个参数的调整我目前实验下来必须在bucket_id 的基础上调试，如果 bucket_id 与图片不适配，产生的视频很糟糕，那么其他两个参数是无法救回来的。

那么，有多少本领就做多大事，我们也尝试使用MidJourney 与 SVD 来尝试做一个劣质版游戏预告：

没错，这类影片，如果要使用 SVD，对输入图片本身就要有一个大概的动画预期，比如我们已经知道了 SVD 擅长做火焰，流水，下雨，落花，烟雾，干净的单人画面等，那么我们在出图的时候就把这些加进去。

前Sora时代终结

在OpenAI官网中，在对 Sora 进行介绍描述时，有一句轻轻带过的话：“图片是单帧的视频”，联系其视频质量甚至是跨越了其已有的图片生成模型DALL·E,是个很有意思的说法。本文中，或者开源社区中在前 Sora时代，很多情况可以说循着相反的一条路“视频是连续的图片”，再考虑到 OpenAI 众多的先发优势，工程积累和trucks of cards，这其中的因果关系究竟是环境影响了思想，还是思想改变了环境呢。
