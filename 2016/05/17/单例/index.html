Java 单例：初始化时机与安全发布

复习单例时，最容易把三个要求混在一起：只创建一个对象、需要时再创建，以及多个线程使用这个对象时不会出错。它们彼此相关，却不是同一个问题。

双重检查为什么还需要 volatile

双重检查锁希望只在初始化阶段竞争锁，后续直接返回已有实例。

在这里，volatile 的关键作用是参与建立安全发布所需的内存可见性与顺序约束。不能把它简单理解为“所有操作都直接访问主内存”，也不能把构造对象看作一个不可分割的瞬间。

另一个线程看见非空引用时，应该能够看见初始化完成的状态，而不是观察到一个尚未按预期发布的对象。

如果单例类上还有其他静态功能，调用这些功能可能先触发该类初始化。这样，单例也可能早于真正需要它的时候被创建。

静态内部类把初始化入口再缩小一步

外部类被使用，并不意味着 Holder 也立刻初始化。直到访问 Holder.INSTANCE，才触发持有者类初始化。这把延迟创建与初始化同步交给了运行时机制，而不需要手写双重检查。

单例的边界要说明白

上面的“一个实例”有类加载器等前提，并不是整个操作系统里永远只能有一个对象。反射、序列化和测试隔离也可能带来额外设计问题。

更实际的一点是：如果这个单例内部有可变集合，或者多个操作需要一起保持一致，仍然需要为状态访问设计同步。保证只构造一次，不等于保证以后怎么用都正确。
